# AutoEpicSeven Development Lessons

本文件整理开发历史和实机排错中重复出现、代价较高且难以仅靠读代码发现的经验。开发历史可能早于当前代码；发生冲突时先检查当前实现和 git 历史，不照抄旧方案。

## 召唤与活动流程

- 常驻池、活动池或免费池必须有可验证的页面/池子锚点；“点击过页签”不等于已经切换成功。
- 免费次数是否用完由游戏页面状态决定，不由脚本猜测固定抽数。
- `SUMMON_SKIP` 和新角色提示是稀有中间状态，不能用它们重置计数或证明下一抽开始。它们没有出现时，抽卡仍可能正常完成。
- 免费召唤的可靠状态是：出现继续免费召唤就继续；结果页只剩返回就保存结果并返回；免费按钮消失并稳定停在目标池时判定今日已用。
- 保存结果需要防止点击未生效造成每帧重复保存。保存标记在当前结果页首次保存后设为 True，只有继续按钮实际点击并进入下一抽后才重置。
- 不用本地 `completed_draws`、`draw_in_progress` 或动画标记代替游戏状态。用户可能已经手动抽过，每日赠送总次数不等于脚本本次应执行次数。
- 活动专用轻触关闭只用于已经验证需要它的状态。例如当前特别活动只在能量饮料流程使用，不把它加入其他领取、任务奖励或免费召唤的通用 handler。
- 仅某一服务器 / 语言支持的活动使用服务器与语言入口分发；不支持组合在任务入口正常跳过和延后，不在模块 import 阶段加载缺失页面或 assets。

## 页面与跨模块跳转

- 同一入口可能恢复到上次停留的子页。把容器页和子页分别建模，入口允许到达两者，再通过二段状态进入目标子页。
- 跨模块跳转优先 `ui_goto(Page)`。私有 `_enter_*` 往往假设调用者已经在模块内部页面，从其他任务直接调用容易超时。
- 页面到达不代表流程可开始。周奖励、结算层、网络弹窗和活动提示可能在入场后出现，需要独立状态循环。
- MENU 返回、顶部 HOME、BACK、关闭 X 和动态返回按钮的目标不一定相同，建边前在实机确认。

## 商品列表与多目标识别

- 商品与 BUY 按钮应按同一行的 Y 中心配对；不要固定取第一个 BUY。
- 小模板在长搜索区域容易产生几十个密集结果。先确认源图和 button extract 已刷新，再考虑增大合并阈值或扩大模板特征。
- 游戏购买后常把商品变暗而不是移除，模板仍可能匹配。每轮最多一个目标类型时，使用“本轮已购”标记，刷新成功后重置。
- 任何导致列表变化的动作后，都要重置稳定计数或扫描门控：刷新、滚动、确认购买、切换子商店。
- 刷新按钮点击后不能立刻扫描旧列表。先处理刷新确认，再等待列表锚点稳定。
- 免费商品可能不是标准“图标 + 右侧 BUY”结构；目标定位与购买确认可以共用，首次点击策略要允许 direct click。
- MAX 与 CONFIRM 有明确顺序时，用状态门控保证 MAX 优先；不能靠 sleep 猜按钮出现时间。
- 共享搜索区域通过 load_search 修改后可能是全局可变状态，跨场景复用同一 asset 前检查是否需要恢复或隔离。

## 滚动与稳定状态

- 惯性滚动时识别坐标会过期。等待锚点连续帧位置稳定后再点击商品。
- “稳定”必须服务于具体状态，例如商品行 Y 位置或列表图像变化；不要把通用 `wait_until_stable` 当固定等待包装。
- 能通过下一页面或确认按钮判断动作完成时，优先状态判断；只有界面没有明确状态时才用短稳定计数。

## OCR 与资源采集

- 可变长度资源数字不要按位数切多套框。优先匹配当前帧资源图标，再在相邻图标之间裁 OCR 区域。
- E7 的行动力、旗帜等计数器当前值可以合法超过恢复上限，例如 `19521/336`、`26/5`。除非字段定义明确是硬上限，不校验 `value <= total`，也不删除“多余前导位”。
- 不使用按字符等宽切分的 fallback 猜字段位置。它容易生成格式合法但字段错位的数据，比明确失败更危险。
- 图标锚定主路径任一关键图标缺失时，整帧作废并重试；不要把部分字段静默写入后再由不可靠 fallback 补齐。
- 图标匹配需要检查横向顺序，避免一个模板误命中相邻货币图标。
- 自动战斗图标导致资源栏整体横移时，由当前帧图标 offset 吸收位置变化；搜索区域按最宽情况覆盖，不必为整体位移维护两套 assets。
-  OCR 字段两侧可能有动态光环或按钮。使用基于布局实测的尾部宽度上限，防止 OCR 把光效识别成数字。
- 调试日志保留原始 OCR 文本。非数字尾巴看似可被解析器过滤，但它通常暴露裁剪边界已经碰到动态 UI。
- Overview 只显示 stored 数据，不做即时 OCR。业务任务在资源变化后触发 DataUpdate，DataUpdate 只保留每个字段必要且可靠的采集页面。
- 冗余采集页面不是保险。若没有新增字段且页面跳转昂贵，就移除重复步骤；涉及删除代码或文件时遵守当前用户“不删除文件”的约束，只做允许的修改或提醒。

## 邮件与外链

- 邮件任务以剩余时间升序的顶部邮件为判断对象，先确认排序状态，不假设一次点击能切到正确排序。
- 调度要根据剩余时间逼近阈值，同一个粗粒度标签持续出现时逐步缩短检查间隔。
- 普通奖励、跳链奖励和角色/神器奖励是不同状态分支，不能只写一个 RECEIVE -> CONFIRM 流程。
- 外链跳转后用 Android Back 回到游戏，避免猜测浏览器或 WebView 目标页面。
- 领取后可能进入召唤式结果页，需要复用经过验证的 NEW、SKIP、NEXT_PAGE、RESULT_BACK 状态处理，但不要复用本地抽数逻辑。

## 宠物与结果关闭

- 结果页和背包已满弹窗可能需要不同次数的关闭动作。用已识别状态决定剩余关闭次数，不用无条件连续点 X。
- 完成后返回稳定页面再调度下一次运行；“免费次数已用”和“领取完成”都可延到服务器刷新，但日志要区分两者。
- 只支持某语言的免费按钮或背包已满资产，要在入口声明支持范围，不写假资产占位。

## 圣域与固定位置奖励

- 固定奖励宝箱靠亮灰区分时使用 `match_color()`；同一位置的 CARE 与 CLAIM 等不同操作必须用不同资产。
- 点击照料后立即获取新截图，新增红点或奖励状态可能短暂出现。
- 仓库满时退出但不要标记月常完成；完成状态与无法继续状态必须分开。
- 周常尚未实现时保持明确 TODO 和安全退出，不用空 OCR 或默认值伪装完成。

## 调试与可观测性

- “识别到了商品但没买”先记录 item matches、BUY matches、confirm、当前页面，以及所有匹配区域。
- “登录后只剩包名日志”通常表示新页面没有任何状态命中；先保存截图补状态，不加 sleep。
- 点击无效先检查下一状态、interval、旧帧扫描和搜索区域，不先延长固定等待。
- 一次性或高资源成本流程优先离线复现；实机失败时保存原始截图、关键状态变量和计时器退出原因。
- 日志中的合法极端值要保留，例如超上限行动力；不要为了让日志“看起来正常”修改真实数据。

## General Decision Rules

1. 游戏有明确状态，就让状态推进流程。
2. 状态短暂或稀有，就不能让它独自承担计数、完成或重置职责。
3. fallback 无法证明语义正确，就明确失败并等待下一帧。
4. 状态变量只描述截图看不到但流程确实需要记忆的事实，并在每个状态变化点写清重置条件。
5. 先补可观测性，再调阈值；先确认生成资产已刷新，再怀疑模板算法。
