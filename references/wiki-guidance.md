# ALAS Wiki Guidance For AutoEpicSeven

本文件把历史文档中的设计概念整理为当前项目规则。

## 运行模型

- 框架面向长时间运行，默认分辨率固定为 1280x720。
- “快”来自状态出现后立即响应，不来自缩短固定等待；固定 sleep 会同时拖慢高配设备并破坏低配兼容。
- 假设点击可能不生效、截图可能偶发损坏、设备可能卡顿。每一动作都要能由后续截图确认并重试。
- 识别开销通常远小于截图开销。优先缩小模板和搜索区域，不要为了少写几个 `appear` 牺牲状态清晰度。
- `GameStuckError` 与 `GameTooManyClickError` 是最终死循环保护，不代替正常状态设计。

## 坐标与图像工具

- point：屏幕点 `(x, y)`，原点在左上角。
- area：矩形 `(left, top, right, bottom)`。
- location：游戏网格坐标 tuple，仅地图类功能使用。
- node：可读网格名，例如 `E3`。
- 优先使用项目现有 area、crop、颜色相似度、颜色计数和进度条工具，不重复手写图像算法。
- OCR 字体预处理交给 Ocr 类；业务模块只提供字体颜色、阈值和结果后处理。

## 调试

- 模块应能脱离 GUI 独立运行；`run()` 负责读取用户配置和编排，其余方法尽量可直接调用。
- 一次性玩法先用截图离线调试。通过 `image_file` 注入图像，再直接调用识别或解析方法。
- 直接测试交互方法前执行一次设备截图，供 `skip_first_screenshot=True` 复用。
- 调试服务器或语言条件注册时，必须在 import 依赖模块之前初始化服务器和 assets 语言。
- 模拟设备不响应时可用项目现有随机丢弃测试工具模拟，但不能把随机失败逻辑带入业务代码。

## 多服务器

- 服务器差异分三层：assets 外观、方法行为、页面节点存在性。只在相应层分支，不把公共流程复制多份。
- 同名控件外观不同，保持同名 wrapper 并分 assets namespace。
- 方法逻辑有小差异，优先使用项目现有 `@Config.when(...)` 或清晰分发入口。
- 页面只在一侧存在，Page 注册与路由边都按服务器条件创建。
- 服务器设置在模块 import 时可能被读取，因此初始化顺序是程序正确性的一部分。
- 调度日期和“今天”按服务器刷新时间计算，不能简单使用本地午夜。

## Decorators

- `@Config.when(...)` 用于同名方法按配置、服务器或设备方式分发，避免业务主体堆叠深层 if。
- 最后定义明确默认分支；不要依赖装饰器无匹配时的隐式行为。
- `cached_property` 只用于进程生命周期内稳定的值。配置、服务器、截图或页面变化后应重新计算的值不能缓存。
- 计时装饰器只用于调试性能，不把日志耗时当状态同步手段。

## Logging

- 日志层级表达结构：任务开始、功能阶段、细分阶段、关键属性。
- 不大量使用 hr、warning 和感叹号；全部强调等于没有重点。
- 状态循环日志记录“为什么动作”“为什么退出”“为什么等待”，而不是只记录坐标。
- OCR 和多目标匹配保留原始候选信息，失败截图保存到功能自己的日志目录。

## Exceptions

- 异常是任务边界的控制信号，不在每个 helper 里宽泛捕获。
- 可恢复识别错误在有明确重试策略的上层捕获，并设置次数上限。
- 不可恢复业务矛盾抛业务异常；游戏未运行、截图后端错误等交给框架顶层恢复。
- 不要 `except Exception: return False`，这会把程序缺陷伪装成“今日已完成”。
- 用户必须清理背包、选择账号状态或手工处理页面时使用 `RequestHumanTakeover`，日志先说明动作。

## Detection Objects

本节只说明识别对象的行为。asset name、文件后缀、目录映射和生成 wrapper 规则见 `asset-task-conventions.md`。

### Button

- Button 的 area 用于识别，button 用于点击，color 用于平均颜色判断。
- 模板匹配成功后产生 button offset，后续点击应使用同一匹配对象，让小幅 UI 偏移自动传递到点击区域。
- 属性覆盖图可分别调整 AREA、SEARCH、BUTTON、COLOR 等生成属性，实际后缀以当前 button extract 支持为准。
- assets wrapper 是代码生成结果，不手工录入坐标。

### Template

- Template 用于位置不固定或只关心存在的元素。
- 多目标模板匹配需要合并相邻结果并做业务几何校验。
- 动态元素可以使用多帧模板，但每一帧应保留稳定、不旋转、不过度依赖背景的特征；帧数越少越好。
- 不对整张 1280x720 图做无边界模板搜索，先根据 UI 布局限制搜索区域。

### Recognition Choice

- 平均颜色适合固定区域状态。
- 模板适合元素存在和偏移定位。
- 模板加颜色适合“先确认对象，再识别亮灰状态”。
- 颜色计数适合形状简单、色彩稳定但不值得制作模板的区域。
- `wait_until_appear`、`wait_until_disappear`、`wait_until_stable` 不应被当作 sleep 替代品；先判断能否并入状态循环。

## Page And UI

- 每个 Page 必须有唯一 check button。若两个页面共享同一视觉锚点，就继续增加第二状态，不要假装它们是同一页面。
- Page link 描述真实可执行的点击边。能双向返回时补齐返回边，不能返回时明确动态返回或关闭规则。
- `ui_get_current_page()` 负责识别当前页，`ui_goto()` 按页面图寻路，`ui_ensure()` 组合两者。
- 跨模块导航使用 Page 图；模块私有 enter helper 只处理已经进入模块上下文后的二段状态。
- `ui_click(..., additional=...)` 处理本次转场专属弹窗；全局弹窗放 `ui_additional()` 或公共 handler。
- 数字索引切换使用 `ui_ensure_index()` 一类带纠错的现有工具，不先盲目对齐到第一页。
- Scroll、Switch、Navbar 等成熟组件存在时优先复用，不手写点击次数推导当前状态。

## OCR

- OCR 是概率识别，不会达到 100%。每次调用都需要格式与语义后处理。
- Digit 失败返回 0、DigitCounter 失败返回零 tuple、Duration 失败返回零时长等默认值可能与真实值冲突；业务层要区分“真实 0”和“识别失败”。
- 可变长度资源栏优先整条/分段 OCR 与稳定布局锚点，不按位数维护多套固定小框。
- 字段映射要依赖当前帧可验证的图标或布局，不用等宽字符切分猜几何位置。
- assets namespace 与 OCR 模型语言严格分离，详细规则见 `autoepicseven-rules.md`。

## State Loop

完整开发圣经见 `state-loop-bible.md`。最关键的执行顺序是：

1. 获取或复用截图。
2. 判断无副作用退出状态。
3. 判断需要重试的点击/滑动状态。
4. 调用通用 popup、网络、奖励等 handler。
5. 无状态命中时继续截图，由局部 Timer 或框架 stuck 保护判断异常。

不要把游戏 UI 的自然顺序再复制为一张手工状态转移表；一个循环遍历可处理状态，游戏本身保证合法顺序。

## GUI And Config

配置生成有三个层级：task、group、argument。

- `task.yaml` 决定任务包含的组。
- `argument.yaml` 决定组里的选项及属性。
- `override.yaml` 覆盖隐藏或锁定值。
- `gui.yaml` 提供其他界面文本。
- 生成器输出 args、menu、generated config、template 和 i18n。

只编辑源 YAML，运行生成器刷新产物。新增任务必须带 Scheduler 组，并在 `config_manual.py` 的优先级中选择合理位置。当前 E7 入口写在 `aes.py`。

配置属性以 `Group_Argument` 形式访问；多值更新使用 `multi_set()`。未绑定组读取到的默认值不代表用户配置已绑定，跨任务配置访问要用项目现有完整数据接口。

## Comments And Maintainability

- docstring 使用 Google 风格，并为跨页面方法写 Pages 输入输出。
- 注释解释状态不变量、异常分支和 UI 反直觉行为，不复述代码。
- 普通函数保持可在一个屏幕理解；文件变大时按业务职责拆分，不为追求行数机械抽象。
- 状态机反复翻车的部分要比普通代码写得更详细，防止后续“简化”重新引入已知错误。
